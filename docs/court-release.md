# 第二步修訂：缺糧朝會 · 多方議政 v15.12

本次依試玩回饋重做決策規則：人物的資訊、方法、授權與承諾影響執行；玩家起草組合政令，三位廷臣及五個利益方對同一政令提出意見。這是供試玩的本機樣板與草稿 PR，尚未部署 Render。

## 如何遊玩

1. 從人物館的「朝堂危局」進入「多方議政」。
2. 閱讀韓信、蕭何、魏徵各自的情報與疑慮，以及殿外傳報。
3. 點選推薦草案，只會填入預覽；也可展開修改主措施、配套、主責執行者與授權。
4. 檢查資源成本、行政負荷、三人的支持條件、五方利益、後續事件及承諾期限。
5. 正式頒布後，觀看即時變化與執行回報；下一回合須處理到期承諾。
6. 完成三回合，查看國勢、人物合作與履約紀錄；可另開一局比較不同安排。

反對意見不等於禁止下詔。資源、互斥措施、行政負荷及到期承諾決定政令能否執行，玩家承擔其後果。混合方案仍有共同資源與時間限制。

## 人物與資料

- 韓信的戰場方法與指揮授權、蕭何的帳籍調度與合作擔保、魏徵的徵用限制與承諾查核，都有相應規則與結果。
- 記憶記錄實際執行、授權、履約和違約；不再因選了其他人的方案而自動扣信任。
- 人物分析面板唯讀目前人物館已保存的深度分析、人物剖析及人格解讀。文章的解讀保留原文，遊戲轉譯另外標示。
- 尚無文章的人物不會自動生成文章，不改寫原 ID、分類或評級。

人物同場、台詞、各項數值與效果都是跨時代架空遊戲改編。史料線索見人物面板及 `court-council-rules.md`；既有文章中的心理推論不作為史實認證。遊戲不呼叫模型 API。

## 存檔與相容性

新規則以 `court-grain-v2` / version 2 固定，使用獨立鍵 `dynasty_court_grain_v2`。保存完整政令、利益方狀態、人物記憶、待結算事件、承諾與結果頁狀態。讀取時從初始狀態重播整份政令並逐欄比對，拒絕不一致或額外欄位。

原有 `court-grain-v1` / `dynasty_court_grain_v1` 保持原規則，首頁提供續玩或查看初版；兩版不互相覆蓋，也不默默遷移。匯入先驗證並顯示版本與進度，再確認取代**相同版本**的本機進度。錯誤檔及跨開窗讀取不改寫存檔。

兩版朝堂存檔均**尚未同步至雲端，也未納入原有十欄資料備份**。換裝置使用朝堂畫面的下載／匯入。人物、文章、魂穿及逐鹿的雲端資料結構未變。

v15.12 可讀較舊的原有完整備份，備份 schema 仍為 1；較舊 App 會拒絕 v15.12 新備份，還原前需更新 App。

## 驗證

```text
node --test tests/*.test.cjs
python -m pytest -q tests/test_userdata.py
```

91 項 JavaScript 與 30 項 Python 測試通過，四段主頁 inline script 語法通過。新增規則測試涵蓋混合政令、資源與行政限制、不同執行方式、支持與反對、履約與違約、延後事件、完整回放與竄改拒絕。

私有 jsdom 功能測試完成三回合的實際 DOM 操作、草案不提前頒布、兩版存檔保全與匯入、錯誤檔拒絕、下載 JSON 驗證、原文顯示與 Markdown 清理、跨開窗非同步讀檔隔離、背景 inert／焦點還原，以及零網路 API 請求。這不等同於真實瀏覽器下載檔案落地。

另驗證「韓信護運＋公開糧帳 → 保留軍糧重排配給 → 韓信護運＋小額賑濟」：先前擔保的糧隊實際交付後，後續協調人手減少，原本超出負荷的混合方案才可執行；三次完整結算預估均與實際結果相符。第一回合共 210 個候選組合，其中 116 個滿足當下規則；並不代表 116 篇獨立劇情。

獨立審查未發現 P1／P2 阻擋問題。審查提出的到期承諾預估遺漏、人物關係尚無後續作用、缺少持續危局壓力已修正。

本輪內建瀏覽器安全政策拒絕存取該本機試玩 URL，因此不繞過限制；本輪 UI 驗證採用本機 DOM 功能測試，並提供試玩頁供人工檢視。**新版實際瀏覽器的視覺排版、鍵盤流程與下載落地仍需人工確認。** 初版曾完成桌面與 375/320 寬度檢查，該結果不替代本次修訂的瀏覽器驗證。
