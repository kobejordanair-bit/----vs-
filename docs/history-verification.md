# 歷史資料查證規則 v1

更新日期：2026-10-02。目標：保存可回查的資料及不確定性，讓原人物庫與歷史背景接通。楚漢資料包 1.1.0 有 301 條主張，提供六案、十八章、三十個閱讀任務使用；覆蓋範圍仍為 curated-slice。

## 1. 每條主張的流程

1. 從現有簡介、長文與場面抽出候選主張，先辨別它是事件、職位、地點、關係、數量或人物解讀。
2. 開啟能實際查閱的原典章節或研究來源，定位相關段落；搜尋摘要只能找來源，不能當完成查證。
3. 拆開可獨立判斷的主張。日期、參與者、角色、地點、成敗與數量不共用一個模糊「已核實」標籤。
4. 保存作品、章節、URL、版本網址（若可取得）、查閱日期、定位片語與短節錄。來源未打開時不得標 opened-and-read。
5. 比對其他篇章。相同史書本紀與列傳可交叉核對，但不是兩個獨立見證；二者有出入時保留各自記述。
6. 保留原紀年與單位；只在有依據時換算。估計、作者解讀、現代定位與遊戲改編分開。
7. 手動核對人物身份、原庫ID和當時職位，通過結構與引用驗證後才納入資料包。

## 2. 審核狀態

| 狀態 | 可聲稱的內容 | 接續處理 |
| --- | --- | --- |
| source-checked | 指定來源中確實有此記述。 | 保留來源限制；必要時尋找異說。 |
| cross-checked | 至少兩處具體記述已比較。 | 記明它們是否出自同一作品。 |
| provisional | 整理或換算尚待確認。 | 介面明示；不作精確日期／硬性數值判定。 |
| disputed | 可指出不同記述或定位爭議。 | 保存 alternatives，不用多數票抹掉差異。 |

不以AI自報信心或百分比代替查證。現有評級、人格文章及遊戲對白是各自的作者詮釋；史籍記述本身也有立場與成書背景。

## 3. 本次楚漢包採用與排除的來源

- 採用《史記》本紀、世家、列傳與月表的可公開查看文本，逐篇保存出處；電子版是查閱載體，原典敘述、後代注與網頁現代編輯欄分開。
- 不把維基文庫／電子月表新增的公元前年欄當成司馬遷原文；本次不進行精確朔日與公曆月日換算。
- 不直接匯入CHGIS或CBDB的受限制資料。這些資源可用於後續來源選型，納入App前按具體版本與授權評估。
- 不引用模型記憶生成的「出處」，不以原文章出現名字自動建立關係，不補造兵力、人口、糧產或城址座標。
- 原庫私人全文不提交本資料包。保留原始備份、ID對應與在本機讀取原文章的能力。

## 4. 兩類核對工作

**人工史料核對：**確認段落支持何種主張、人物與地名是否同一實體、日期精度、角色範圍及異說。資料包附核對紀錄與未完成事項。

**機器一致性核對：**拒絕重複或懸空ID、角色引用錯誤、非法年0、倒置時間、循環先後、缺來源與不符合包範圍的資料；對未知、不確定與資料缺漏作明確回應。

兩者都完成才可稱「來源核對及一致性驗證通過」。不能稱全部史實已定論，也不能稱整段楚漢史已完整收錄。

## 5. 後續修訂

新資料以新增主張或有紀錄的更正處理，保留原來源。相互矛盾的主張可並存；遊戲自行選擇採用哪種改編，並顯示所用資料版本。新增另一個年代／地區時，沿用同一格式，先定覆蓋範圍再蒐集。

## 6. 從已核主張編成調查任務

案例的背景、問題和引導語是編輯整理，不得冒充出土文書、密信或當事人逐字錄音。單選、多選與排序每個選項的回饋都要能追到真正支持或反駁它的 claim ID。錯誤選項應明確留在待判讀的題目中，不能混進資料包成為事實。

任務可以核對發言者、行動或提案的差別、原篇順序、當時角色、來源關係與已知精度。不得以對錯題裁定人物內心真相、終身忠誠、道德高下，或沒有證據支持的唯一因果。結案由玩家提出自己的解釋、反證或替代解釋、未解問題，系統只檢查必要欄位與材料是否齊備。

本次 20 條補充主張保存於 `investigation-supplement.json`，包含實際開啟來源的日期與定位段落。產生器逐項比對來源 ID 與經字元／空白正規化的定位文字；同一來源已讀過其他段落，不足以讓未核讀的定位通過。資料區分曹無傷的告發、沛公的辯解、蕭何的薦舉、李左車未採用提案、龍且所引理由、彭越自陳，以及鄂君論功的回顧話語。沒有把引述和作者歸因改寫成已證實的心理或客觀數量。

若材料中的人物尚無本包身份節點，保留其名字和缺漏說明，不為了方便做角色卡就假造原庫對應。濰水戰前未具名的說者保持匿名；同一作品多篇相合也不自動增加獨立證人的數量。

## 7. 原人物文章與書桌紀錄

人物原典能讀取完整 962 筆私人快照，不表示所有條目已完成史料查證。現阶段楚漢包仍精確連接 19 位歷史人物的 20 個原庫條目。原分析、五維與評級保持作者／AI 解讀標示；缺少長文不影響完成案卷，亦不得為此補造分析。

原分析段落可作玩家支持、質疑、脈絡或未定材料。localStorage 與書桌匯出保存 ID、欄位、段號、內容指紋和玩家筆記，不自動存原文章全文。玩家自行貼進筆記的原文會被包含，與系統自動複製全文是不同情況。

重新讀取原庫時，段落有變、全文其他部分有變、身份不符或缺少原文都需顯示；不能只因段號相同就把新文當舊證據。舊版無指紋引用需重新核對；內容指紋僅用來檢查變動，不能當作史實可信度或作者認證。

每份評議記錄資料包與案件集版本。版本變動後仍可保留舊評議供參照，不能自動宣稱它通過新資料的閱讀任務。匯入與復原先驗證，再保留不同版本；無法理解的存檔不應自動覆寫。這些保存規則維護的是玩家工作可追溯性，並不使玩家評議成為已核史實。

## 8. 發布前核對

發布時同步核對共用包、案件集與讀取器宣告的版本，確認建置可重現、引用存在、任務答案只涉及可判讀事項，並檢查原人物全文未被帶入公開檔案。執行方式見 [啟動及發布指南](history-investigation-release.md)。

資料一致性、程式測試、實際來源核讀和玩家試玩，各自回答不同問題。測試通過不能替代來源查證，也不能證明所有玩家會喜歡目前玩法。未完成的年代換算、精確定位、生卒與經濟數量需繼續明示，不以介面完整掩蓋資料缺口。
