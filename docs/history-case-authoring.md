# 楚漢史論卷一：內容與編寫規則

這一卷讓玩家以原人物庫與有出處的歷史記述，完成自己的評議。六案都能直接開啟；閱讀任務協助玩家辨認材料，結案由玩家自行提出解釋、反證與未解問題。任務評量不等於對人物或玩家的道德評分。

## 已完成的內容

`backend/static/data/history/chuhan-cases.v1.json` 包含 6 案、18 章、30 個任務、121 個帶個別回饋的選項。任務分為 16 個單選、9 個多選、5 個排序，引用共用資料包的 45 條不同主張。每案約 22–30 分鐘是編輯估計，尚未經玩家計時驗證。

| 案件 | 三章的進程 | 人物評議的核心 |
| --- | --- | --- |
| 鴻門：一場宴會，幾套計畫 | 夜間傳訊 → 同席異動 → 離席與留後 | 多人行動如何接續；同一陣營是否有共同意志 |
| 南鄭：一位逃亡者如何受任 | 誤報與追亡 → 目標、職位與禮遇 → 受任後的說辭 | 推薦如何取得信任；怎樣處理後見之明 |
| 下邑至固陵：承諾如何變成合軍 | 推薦對象與身份 → 未赴約與許地 → 紀年與解釋範圍 | 合作條件、自陳理由與他人推測如何並列 |
| 井陘：一條沒有採用的計策 | 未採用提案 → 偵察與部署 → 戰後問策 | 勝利依賴哪些條件；失敗人物能否繼續提供意見 |
| 濰水：追擊之前，還有另一種提案 | 救援前因 → 持守或交戰 → 渡河與反應 | 對敵評價、求功及分地預期怎樣影響行動 |
| 蕭何：沒有在前線的功勞 | 圖書與授權 → 供給及局部斷糧 → 不同功績標準 | 組織與恢復能力如何被描述、衡量及質疑 |

六案共用同一批人物、時間、地點與勢力身份。人物的當時職任從事件資料取得；案例文字不另建立一套永久性格或勢力歸屬。背景、問題和引導文字是現代編輯整理，沒有冒充出土文書、當事人密信或現場逐字錄音。

## 資料如何分工

共用包 `chuhan-foundation.v1.json` 保存人物身份、事件、主張及其來源。案例書只用 ID 指向那些材料，並增加章節、問題、選項、回饋、人物閱讀提示及開放結案。

本卷另外核讀《史記》卷007、053、055、090、092及卷008的相關段落，新增 20 條細分主張於 `data/history-research/investigation-supplement.json`。其中 4 個來源承載新增主張，其餘用來核對既有記述。建置程序把補充主張與附著關係整合回共用包 1.1.0，成為共用的證據層。案例不保存另一套未驗證史實。

新增主張保留了以下差異：

- 告發內容與告發已獲證實不同；沛公守關的說明仍屬當事人辯解。
- 蕭何被報逃亡與實際追趕韓信不同；韓信論項羽的話具有遊說場景。
- 李左車提出而未採用的方案，不會標成趙軍已執行的戰果。
- 濰水戰前說者未具名；不能為了顯示人物卡而任意配給知名謀士。
- 彭越自陳魏地未定，與張良分析許地問題，保留不同發言者。
- 漢五年戰後論功屬回顧性話語，與跨期供給機制分開標記時間。
- 長期轉漕、局部斷糧與功臣讚譽各有尺度，不能互相覆蓋或換成虛構庫存。

李左車、曹無傷、項莊等姓名出現在已核段落中，但這次沒有新增其人物節點。相關主張明示缺口；人物視角與原庫連接只使用已有的精確身份。

## 一案的共同結構

頂層識別為 `format: dynasty-history-casebook`、`schemaVersion: 1`，並聲明共用包 ID 與版本。每案有穩定 `case:` ID、排序、主題、難度、時間估計、情境、調查問題、事件／人物／主張引用。

每章有 `chapter:` ID、簡介、主張清單與任務 ID。任務以 `task:` ID 識別；每個選項有局部 ID、文字、個別回饋與支持回饋的主張 ID。單選、多選使用 `expectedChoiceIds`；排序使用 `acceptableOrders`，可在確有多種相容次序時列出多個合法排列。

人物視角 `perspectives` 包含人物 ID、閱讀角度、主張 ID 與原分析提示。它幫玩家回到原人物館，不替角色製造新的分析全文。

每案結案包含主問題、延伸問題與結案說明。最低材料要求是 2 項公開主張；原庫材料最低為 0，避免把缺少長文的人物變成無法完成的障礙。解釋、反證和疑問的最低字數，只用來避免空白提交，不能宣稱已驗證推論品質或文章真實性。

## 任務可以判什麼

可以客觀核對的是來源的用法：一段話由誰說、是否為已發生的行動、記述順序、當時角色、不同篇章的關係，以及資料包已明示的未知。多選必須明確要求「選出所有受到材料支持的說法」；排序只要求來源真正支持的先後，不能拿現代日期猜測補出順序。

錯誤選項是待判斷的整理方式，並非新增史實。回饋需要指出它跨過哪一層證據：引述被當成事實、提案被當成結果、後來職任被提前、局部記述被外推、或未知值被補成數字。每個選項皆可回查對應主張，避免只顯示一個對錯符號。

不能判定的包括人物內心真相、終身忠誠、道德高下，以及某位人物是否為某場勝利的唯一原因。任務通過只表示讀法與本案材料相容；玩家在結案可以採用不同的衡量標準，也可以保留兩種尚不能分出高下的解釋。

單一問題若需要史料以外的研究才能回答，應補查形成主張，或改寫成開放問題，不能拿模型印象充當答案。

## 原人物庫如何真正參與

首包的歷史身份經 `libraryRefs` 連到原 ID、姓名和分類。劉邦與漢高祖對應同一歷史人物，但兩個原庫條目和各自文章仍各別呈現。後世帝號不會因此變成鴻門的當時職稱。

2026 年 9 月 30 日保存的 962 筆快照中，本卷重點人物的長文分布並不平均：韓信、漢高祖、項羽有分析、深度分析與人格精髓；張良有深度分析。蕭何、彭越、龍且、陳餘等重點人物在該快照沒有這三類長文。這是該份快照的欄位盤點，不代表雲端今後的內容永遠相同。

引導文字因此會具體提示：從現有長文挑一段，檢查其中對謀略、知遇、納諫、用人或功績的解讀，找到支持它、使它變複雜或使它需要修正的事件材料。玩家也能選擇原簡介或不使用長文，不會被要求杜撰一段不存在的分析。

原分析始終標示為原庫作者／AI 解讀。使用者可以引用、支持、質疑或修正它，但引用不會使它自動變成已核史實。公開案例檔沒有複製私人長文；保存和匯出應依工作台的隱私規則保留原 ID、欄位與段落索引，不能默默把全文加入公開資料包。

## 結案與下一次重讀

玩家留下自己的解釋、反證或替代解釋，以及仍未解決的問題；評議應可追到所選材料。系統可以提示材料不足、缺少疑問或欄位空白，也可記錄任務完成情形；不能把材料數量或字數變成歷史判斷分數。

重讀價值來自換一個人物視角或衡量標準，例如鴻門從張良改看項伯，井陘從韓信改看陳餘，供給卷從前線戰功改看失利後的恢復能力。玩家可以回到同一份材料改寫結論，不需要系統假造新史實或強迫答題導向同一人格標籤。

這套內容可支援完整的一次閱讀與評議，但「是否好玩」「是否願意重開另一案」仍需實際試玩觀察。不要把任務數、資料量、結案率或無 AI 呼叫，單獨當成已驗證娛樂性的證據。

## 查證與修訂門檻

新增案件前，先確認相關人物在原庫有什麼內容、史料能支撐哪些互動、哪些人仍未有身份節點。每一項可判對錯的敘述都要對應真實 claim ID；每一個 claim 再回到實際核讀過的篇章與段落。不得只依搜尋摘要、記憶或生成文字聲稱完成查證。

變更原典摘要、角色或事件範圍，先更新共用主張與查證註記，再檢查引用它的所有任務與回饋。若改變主張的含義，應使用新 ID 或明確版本遷移，避免已存評議不知情地換了證據。只修文字標點也應保持案例可重現。

來源更新時需核對：網址、實際讀取日期、段落定位、主張的敘述者、提案和結果的界線、原紀年，以及仍存在的異說。維基文庫在此提供古代公共領域正文的轉錄；本卷沒有把現代註解、機構圖片或未授權長文整批複製進遊戲。

本卷已做獨立的引用檢查：所有 case、chapter、task ID 唯一；事件、人物、主張存在；章節與任務互相指向；答案引用合法選項；排序包含各選項恰一次；每個人物視角屬於該案人物；所有選項主張屬於該案材料池。這些檢查證明引用與結構自洽，不能代替歷史研究與玩家體驗測試。
