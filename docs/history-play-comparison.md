# 同一份人物與史料，三種玩法樣本

這一頁先比較玩家的操作方式，不先決定完整遊戲要採哪個方向，也不預先宣稱已驗證好玩。它獨立於人物館與既有戰役引擎；三種模式都讀取 `chuhan-foundation.v1.json`，使用同一份資料格式與引用關係。

人物庫的 962 筆記錄仍是原始資料基礎，但目前只把首包能核對的人物身份連結到事件；不把 962 筆都宣稱為已完成的遊戲角色。人物館的帝王、將帥、謀臣分類與事件當時身份分開。劉邦的帝王類與將帥類記錄分開呈現，沒有把後來的稱號倒推回早期事件。

## 本頁可以操作什麼

| 樣本 | 玩家反覆做的事 | 原資料如何實際參與 | 現階段不成立的推論 |
| --- | --- | --- | --- |
| 時空探索 | 選年份區間與人物／地點／勢力，追查事件、角色、關係、移動與供給材料 | 事件與職任有來源；人物名稱能回到原庫身份與完整分析 | 年帶相交不等於確定該年；地名不等於精確座標；供給記述不等於可計算的庫存 |
| 史論調查 | 選問題，自選支持、質疑、脈絡與未定材料，留下暫定解釋與疑問 | 史料主張與原分析段落一起進入調查桌；人物原文不是僅供閱讀的側欄 | 同一作品的多章不一定是獨立證人；作者／AI 解讀不是已核史實；材料多不代表答案正確 |
| 人物編排 | 選事件與人物，核對當時角色、行動、提及、參與不明與資料缺口，再記下創作構想 | 原庫身份與分析全文可查，事件關係與參與方式回連史料 | 同事件不等於同室；未記載不能判不可能；只有明確不相容的生卒範圍才提示須標架空 |

## 原人物分析怎麼進入調查

1. 在史論調查選人物，或在其他模式點人物名稱。
2. 原庫每筆身份、每個分析欄位各自呈現。完整原文以純文字保留，不執行 HTML。
3. 在「人物分析」「深度分析」「人格精髓」各欄選取段落，加入指定調查。空白欄位清楚標示缺資料。
4. 調查桌同時顯示史料主張與原庫分析，後者標示「原庫作者／AI 解讀 · 未核史實」、原始 ID、欄位與段號。
5. 玩家可把原庫解讀視為支持、質疑或脈絡，自己撰寫判斷；不由 AI 評分或產生固定人格。

段落按空行分隔；只有一個區塊時按換行分隔。加入後在本頁記憶體保留當時文字，重新載入另一份人物檔不會默默改掉已選材料。下載只保存原始 ID、欄位、零起算段號與玩家分類，不包含人物全文；自行撰寫的筆記會下載。

## 資料流程與成本

```text
共用 schema + 楚漢首包
          ↓ 驗證結構、ID、時間與引用
     DynastyHistory 索引
          ↓
 時空探索 / 史論調查 / 人物編排
          ↑
 內建人物庫，或本頁唯讀匯入的本機 JSON
          ↓ 按原 ID + 姓名 + 分類匹配
 原文閱讀 / 原分析段落作調查材料
```

公開頁面僅請求本站資料包與 schema。人物檔在本頁記憶體解析，不上傳、不寫入人物館、不使用 localStorage 或 IndexedDB。沒有 AI 或計費 API 請求，每次操作不消耗 token。

私人 loopback 預覽在 `?local=1` 且主機為本機時，才嘗試唯讀 `/private-library.json`，標示為 2026-09-30 快照。人工讀取新檔會阻止較早的私人快照請求覆蓋它。檔案格式錯誤時保留既有資料和筆記。關閉本頁後未下載的筆記不會保留。

## 本次樣本的驗收方式

### 可核對的操作

- 相同人物換到不同事件，事件脈絡、角色與參與標籤從資料變化，不能靠固定人物函數決定。
- 同一件事件選不同人物，能看到在場／行動／提及／未知的差別及對應來源。
- 調查能選反證、保留紀年異說，能把原庫分析段落實際放進調查桌。
- 加入原庫材料不會讓它變成史籍記述，也不會轉成能力值或心理答案。
- 三種模式仍能追到共用 claim、章節與來源網址。
- 人物原文缺失、身份未連結、資料包讀取失敗都有明確狀態。

### 需要玩家試玩才知道的事

觀察使用者是否願意自行追查事件、是否會尋找反證、是否能把原分析轉成有根據的解釋，以及編排人物是否引發想繼續創作的動機。這些觀察用來選下一個完整遊戲核心；目前頁面不以點擊數、材料數或 AI 分數預測好玩程度。

## 尚待補齊的邊界

本包只是楚漢關鍵事件切片，不是完整年表、全人物生卒、全部諸侯勢力或經濟模型。古地名的現代定位、史籍紀年的公元換算與不同篇章的記述差異，必須保留各自精度與缺口。要做戰略遊戲仍需另補可以運算的供給、運輸、勢力變動與規則層；不能把這些定性材料直接當遊戲數值。

可重用的是共用資料包、引用索引、原庫身份連結、證據卡與三種操作記錄。之後可替換互動流程或增加遊戲規則，無須先把原庫全文改寫成固定人格。

## 用首包比較後的初步判斷

這次實作使用 22 件事件、14 項來源，從鉅鹿、入關與鴻門，到韓信受任、下邑聯合構想、固陵與垓下。來源含《史記》章節與現代定位報告，不能把 14 項都稱為原史籍章節或獨立證人。以下是根據資料與操作結構的產品判斷；目前仍是玩法樣本，尚未經實際玩家驗證。

| 方向 | 首包已能支撐的反覆操作 | 可玩化還欠什麼 | 選它的條件 |
| --- | --- | --- | --- |
| 時空探索 | 跟著同一人物跨事件查職任；例如韓信由大將到齊王，或由下邑「被推薦」追到後續實際行動 | 明確的探索目標、線索發現與回訪理由。目前主要是篩選與閱讀，不能把點開證據卡就當成遊戲進度 | 玩家自發追下一件事件，並能說出身份或關係如何改變；若只快速搜尋姓名，較適合作導航層 |
| 史論調查 | 從不同篇章選材料，保留英布歸漢、固陵等紀年差異；把原庫分析段落加入支持、質疑或脈絡，修正自己的解釋 | 有吸引力且能由材料處理的問題、材料負擔控制、一次調查的明確收束。首包異說多涉及紀年，尚不能據此設計所有人格問題 | 玩家會主動找反證，能指出分析中的解讀與史籍記述差別，並願意留下自己的說明；若只等公布唯一答案，應另調整核心 |
| 人物編排 | 比較下邑被提及的三人、固陵未會兵者與垓下有行動記述者；同一批人物換事件，參與標籤與角色會不同 | 場景目標、玩家創作形式與回饋。史料能約束角色，卻不會自動給對白、情緒或戲劇衝突；原分析仍需由玩家有意識選用 | 玩家願意用角色脈絡寫短場景或策展說明，並標出哪段有依據、哪段是創作；若只勾選人物看標籤，暫宜作延伸工具 |

**史論調查目前最直接使用原人物長文的價值，可作候選核心。** 玩家能拿原分析的一段解讀，與另一位人物的分析和事件史料比較；原文不必先被壓成固定能力或性格。這個方向成立的前提是玩家願意閱讀、比較與形成解釋，也有足夠相關分析可選。只有簡介、缺分析的人物，應用身份、事件與已核史料加入探索，不能為湊齊角色而補造人格。

可先試一個完整短循環：選一項可爭論的解讀 → 找支持與反證 → 選相關人物原分析段落 → 修正說明 → 完成一張有來源、仍保留疑問的人物評議卡。時空探索提供尋找事件與人物的入口；人物編排承接想把理解轉成場景或展覽的人。評議卡與場景是下一步候選，目前頁面只提供材料桌與筆記，尚未實作完整收束或獎勵。

第一個觀察點可選下邑與固陵兩件事件：讓玩家自行比較張良的原分析、韓信或彭越的原分析，與推薦、承諾及未會兵的記述。問題是「這些材料支持哪些解釋、留下哪些疑問」，不能把它改成「某人天生忠誠／貪利」的唯一答案。若玩家能引用至少一段原分析與一項史料、察覺一處材料不足，並產生想追查的下一題，才有理由繼續深化調查循環。

這個驗收觀察的是操作是否引發解釋與追查，不是材料數量達標便算成功。若玩家反而更投入跨事件尋人或場景創作，就應依觀察調整主次。三個入口共用資料，可以交換核心，無須先大量擴充人物或重做年表。
