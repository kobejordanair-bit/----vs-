# 共用世界規則與整合契約

本文件對應 `world-engine.js` 的 `VERSION = 1`。這是 v16 世界書桌使用的確定性規則引擎；原有逐鹿、魂穿、評鑑、對話、辯論與朝堂引擎繼續保留。

## 一、資料如何進入玩法

1. 從正在使用的人物庫，依 **原始 recordId** 選 2–12 份紀錄。同名人物仍是不同紀錄。
2. 凍結這一局使用的姓名、分類、原庫五維評值，以及使用者選取的原分析片段。修改人物庫不會改寫已建立的局。
3. 可以指定資料包中已整理的事件、時間、地點、勢力及來源 ID。歷史切片需有 eventId；自由架空可不指定。
4. 開局保留所有原始參照，另建遊戲用地域與勢力席位。防務、資源、軍事反應、期限、關係及遊戲結局均是規則假設，不宣稱還原真實歷史。
5. 原文片段可僅作閱讀依據，或由玩家親自指定「我的解讀」原則。引擎不從姓名、文字或人物類型猜測歷史人格，不判定引文真偽。

每位人物另凍結 `sourceContext`：歷史人物 ID、所選事件的角色及參與狀態、查證狀態與限制說明。尚未連結事件身份者明示為創作角色，不能因同局選了歷史背景就宣稱確曾參與。這份身份脈絡不產生額外屬性加分。

玩家的世界筆記保存於 `config.setting.notes`，最多 6,000 字元，預設空字串。它隨開局凍結，供世界閱讀與可選敘事使用；筆記是玩家創作脈絡，不參與資源計算、不升格為史實，也不作為可執行指令。匯出、匯入及 `getScene` 均保留原文，直接修改既有存檔中的筆記會使設定一致性驗證失敗。

原人物文章、私人檔案與遊戲存檔相互獨立。引擎不改寫人物庫、不發網路請求、不使用模型。可選 AI 敘事由外層介面呼叫，敘事不能改變規則結算。

## 二、完整回合循環

一局 8–12 回合，預設 10 回合。每回合是遊戲的一旬，不會把參照年代自行換算成未經查證的歷史日期。

每一回合依序處理：

1. 檢查人物、地域、目標、指令組合、協調容量與現有資源。
2. **先付款**，包含本次措施及選擇付清的到期義務。不能用尚未產生的徵調收入墊付。
3. 履約、延期或違約，責任仍歸原先受命者。
4. 執行主措施及配套，建立新的義務或延後交付。
5. 已到期的制度改善交付。
6. 例行軍民配給與行政維持，再結算本局常規農務及收入。
7. 外部軍事勢力、商路聯盟、地方權勢各自反應。
8. 民生、議政、防區及地方不安造成後續壓力。
9. 計算人物疲勞、經驗、信任、合作；套用有限的原文原則實踐效果。
10. 魂穿局另結算適應、聲望、自我維持、身份張力及宿主社交圈。
11. 保存完整政令、成本、實際增減、能力來源、來源參照與對手行動；檢查結局。

相同開局與政令得到相同結果。行動預覽顯示包含維持成本、收入及敵方反應的完整預計結算；不是只列正面收益。

## 三、指令與有限資源

### 主措施

| 措施 | 用途與取捨 |
| --- | --- |
| 整備農務與糧倉 | 花府庫補糧；重複動員的額外收益遞減，仍有農戶負擔 |
| 議價採買與通商 | 先付採買款；指定地域的安全影響到貨 |
| 限額徵調與籌款 | 迅速補款，損害民生與公信；重複徵調收益遞減 |
| 賑濟與恢復生計 | 以糧款改善民生、公信及地方秩序 |
| 築防與輪換守軍 | 強化指定防區，留下接續糧餉義務 |
| 踏勘與交叉查訊 | 指定地域取得兩回合情報，支援防禦與後續行動 |
| 有限軍事施壓 | 指定對手；情報、供給、軍備、能力與授權影響戰果及損失 |
| 締約與利益交換 | 只影響選定一方，仍須支付盟約貢付；其他兩方繼續行動 |
| 試行制度改革 | 先投資及承擔議政阻力，後續才交付；每地最多三期 |
| 募補與部隊整合 | 花糧款補軍備，影響民生並留下續餉義務 |
| 研讀與處境適應 | 增加研習與行政，魂穿局加速適應 |
| 整頓、休息與配給 | 降低疲勞，時間、供給及對手壓力照常推進 |

配套另有護運、公開帳目、補償憑據、民軍協商、反滲透、訓練、整理史料及共同走訪，也可以保留人手。主措施與配套須由不同的實體人物負責。

能力使用原庫的統率、武力、智力、政治、魅力。每項措施有公開使用的兩個維度，並顯示疲勞減益、信任減益及本局經驗增益。若原庫缺少評值，使用全五十的中性起點並明示，不能把預設值稱為歷史評價。

所有資源與關係都是 0–100 遊戲刻度。正常協調容量為六，議政支持低於三十降為五。積極授權、過度疲勞及處理到期承諾會增加容量需求。

### 到期義務

- 築防、募補、締約、補償會形成未來款項。
- 到期必須選付款、延期或公開違約，預設建議是付款。
- 延期只允許一次，每筆府庫追加三點並承擔公信代價；不能延到結局以後。
- 違約影響原責任人、共同信任及相應受益方。換一位執行者不會洗掉責任。
- 最後一回合建立的義務當場備款，不能以「未來再付」取得免費收益。

## 四、多方壓力與地理參照

世界有民生腹地、邊境防區、交通商路三個遊戲地域。可連回真實 placeId，但它們是規則使用的區域示意，不能當作考證疆域。

外部競爭勢力找防務薄弱處試探；商路聯盟可封鎖或收取通行費；地方權勢會依公信與授權配合或阻撓。它們各自保存實力、敵意、關係、停戰期限與最新行動。

- 民生低於三十五：公信與行政受損。
- 議政支持低於三十：協調下降、公信受損。
- 任一防區安全低於三十：軍民維持成本上升。
- 當地不安達七十：防務與交付受損。
- 糧儲連續兩回合耗盡，或軍備、公信歸零：可能提前結束。

補強一處後，對手可能改探另一處。與一方締約，不會自動令其他方停戰。

## 五、魂穿使用同一個世界

魂穿須指定不同的 hostId 與 soulId，兩者都必須在本局人物清單內。靈魂沒有第二具可任命的身體；若要同時執行配套，需要再選至少一位人物。

| 方法 | 能力與身份後果 |
| --- | --- |
| 依宿主原有方法 | 使用宿主評值；身份張力降低，穿越者自我維持略降 |
| 以穿越者方法介入 | 按適應度混合能力；適應較快、張力較高，低適應時社交圈會疑慮 |
| 雙方折衷 | 漸進混合能力；適應、合作與公開交付有助降低張力 |

只有宿主本人受命時，能力才會混合宿主與穿越者評值。把工作交給第三人仍使用第三人的能力。穿越者方法不是跳過宿主身體限制的全值替換。

研習加速適應，共同走訪改善宿主關係，公開帳目幫助交代行事改變。高張力損害議政與公信；張力極高且原有關係崩落會造成身份決裂。

這些關係只描述本局共同經歷，不宣稱任何人物在歷史上認識、信任或敵視另一個人物。

## 六、原分析如何影響行動

每則錨點保存原文 quote、原欄位 sourceField、簡短標題 label、玩家自己的 interpretation、來源參照，以及玩家選定的 principle。

| 玩家選定原則 | 相容 | 明確相違 |
| --- | --- | --- |
| 民生優先 | 農務、賑濟、休整或民軍協商 | 無補償徵調、軍事施壓 |
| 組織秩序 | 築防、改革、募補或公開帳目 | 公開違約、積極授權的徵調 |
| 進取冒險 | 軍事施壓、改革、募補或積極授權 | 審慎限額的休整 |
| 協調聯盟 | 締約、民軍協商或共同走訪 | 軍事施壓、公開違約 |
| 調查學習 | 踏勘、研習或整理史料 | 未有有效情報的軍事施壓 |
| 只作閱讀脈絡 | 原文留在回合紀錄 | 無數值效果 |

同時命中相容與相違時，依相違處理。這是玩家選擇遵守的遊戲約定，不是對人物真實人格的判定。

每位人物的每則錨點，前兩次相容實踐可給主要受命者信任 +3、共同執行者合作 +2；若受命者是魂穿宿主，再給適應 +2。第三次起只記錄、不再獎勵。相違則信任 -3、共同合作 -1；魂穿宿主張力 +2。沒有對應行動則中性。

未選 principle 的舊式錨點預設 `none`，不因引用字數、文采或人物名望加分。原文的真偽與查證仍回到史論館及來源檔案館處理。

## 七、結局與局限

爭霸結局依資源、壓制對手、締約與治理形成有限優勢、多方共存、民生基礎或脆弱平衡。魂穿結局另考量適應、張力、聲望及宿主社交圈，可形成共同承擔、處境改革、身份爭議或守住日常。

結局保存當時的資源、關係與未解義務；不宣稱為人物的真實命運。內部合作成功也可能留下薄弱軍備，結局不等於所有問題都已解決。

本版是完整的有限回合遊戲，不是開放式歷史宇宙。各場景共用規則；目前的經濟、兵力與敵方策略是明示的遊戲設定。進一步加入特定歷史事件的專用規則，需要另做有來源的資料與玩法設計，不能用模型臆造填補。

## 八、程式介面

瀏覽器全域 `DynastyWorld`；Node 使用 `require('.../world-engine.js')`。資料均為 JSON，不依賴 UI、儲存庫、目前時間或網路。

| 方法 | 回傳 |
| --- | --- |
| `createSession(config)` | 新的完整 state |
| `describeActions(state?)` | 主措施、配套、風格、履約、魂穿方法、玩家原則及資源中文名稱 |
| `getScene(state)` | 地域、勢力、人物、壓力、到期義務、待交付事項及原文精確 ID 連結 |
| `defaultOrder(state)` | 完整政令骨架；有到期義務時預設 pay，仍須預覽確認付款能力 |
| `getActionPreview(state, order)` | `valid, errors, cost, capacity, notes, abilities, expected, consequences, due, newCommitments, anchorApplication` |
| `resolveTurn(state, order)` | 新 state；不改動輸入 |
| `reduce(state, {type:'turn', order})` | 同 `resolveTurn` |
| `validateSession(state)` | `{valid, errors}` |
| `exportSession(state)` | `{format:'dynasty-world-save', version:1, state}` |
| `importSession(objectOrJSON)` | 驗證後新的 state；失敗拋 `INVALID_SAVE` |

`expected.resources` 是整回合實際增減；`expected.after` 是結算後完整資源。`log.events` 與 `log.opponents` 中的 effects 是受 0–100 上下界限制後的實際改變，逐項相加等於 `log.delta`。

### 最小範例

```javascript
const state = DynastyWorld.createSession({
  mode: 'hegemony',
  seed: 'my-world-1',
  maxTurns: 10,
  setting: { title: '我的群雄世界', kind: 'fictional' },
  roster: [
    { recordId: first.id, name: first.name, type: first.type, stats: first.stats },
    { recordId: second.id, name: second.name, type: second.type, stats: second.stats }
  ]
});
const order = DynastyWorld.defaultOrder(state);
order.primary = 'harvest';
order.secondary = 'ledger';
order.supportId = second.id;
const preview = DynastyWorld.getActionPreview(state, order);
if (preview.valid) {
  const next = DynastyWorld.resolveTurn(state, order);
  const save = DynastyWorld.exportSession(next);
}
```

完整政令固定有十個字串欄位：`primary, secondary, actorId, supportId, regionId, targetFactionId, stance, settlement, approach, anchorId`。無配套、無目標、無原文以 `none` 表示。只有軍事施壓及締約需要非本方目標勢力。

### 儲存邊界

- 存檔以設定一致性指紋檢查開局，再從 `config + orders` 重新結算，逐欄比較完整 state。直接修改資源、日誌、關係、結局、來源或未出場角色的身份脈絡即拒絕啟用。
- 這是內部一致性驗證，**不是數位簽章或史料真實性認證**。使用者可以合法另開一份不同設定的新局。
- 拒絕未知欄位、無限數值、函式、異常物件、原型污染鍵、過深結構及過大的存檔。
- 每人最多八則錨點，每則 quote 最多 2,400 字元、interpretation 最多 1,600、label 最多 120。
- 每組來源參照最多 80 筆且序列化後不超過 24,000 字元；完整開局不超過 240,000 字元，為 12 回合重播留足空間。
- 存檔上限 1,600,000 字元；匯入先驗證再啟用，不執行資料中的程式或指令。

## 九、驗證

`node --test tests/world-engine.test.cjs` 檢查完整爭霸及魂穿路徑、不同結局、複合指令、三方反應、身份與能力差異、原文實踐上限、付款順序、延後交付、到期責任、結局負債、逐項可解釋資源增減、無模型請求，以及存檔重播與竄改拒絕。

這些是引擎測試。介面、雲端權限、備份和部署需另由整合測試驗證；測試通過不代表已做真實瀏覽器視覺驗收。
