# 史論館啟動與發布指南

新增的全人物來源工作台見 [人物來源檔案館使用與交付說明](source-archive-release.md)。人物閱讀視窗可以依原始 ID 直接連到其來源檔案；原文章與史論案卷仍保留。

這次工作台使用楚漢資料包 **1.1.0**、案件集 **1.0.0**。共有 301 條主張、6 案、18 章、30 個閱讀任務，以及案卷館、時空探索、人物原典、自由調查、創作工坊五個入口。所有數量描述這份楚漢切片，不代表 962 筆人物都已完成史料化。

## 本機開啟

在專案 `app` 根目錄執行。獨立預覽服務使用 Node 內建模組，無需資料庫、模型金鑰或另裝 npm 套件。

帶入本次保存的 962 筆私人快照：

```powershell
node scripts/serve-history-preview.cjs --port 8877 --library "../資料備份_2026-09-30/962人物完整資料.json" --snapshot-date 2026-09-30
```

然後開啟 [史論館私人預覽](http://127.0.0.1:8877/history-lab.html?local=1)。終端需保持執行；停止服務可在該終端按 Ctrl+C。這是唯讀載入保存檔，不是重新同步雲端人物資料。

公開專案不附私人快照。沒有該檔案時，直接用內建人物庫：

```powershell
node scripts/serve-history-preview.cjs --port 8877
```

開啟 [史論館](http://127.0.0.1:8877/history-lab.html)。六份案件和公開史料仍可使用；需要更多人物時，展開「我的人物庫與書桌」→「讀取人物 JSON」，選自己的完整人物檔。

人物匯入支援完整陣列、characters 包裝，以及原 App 的 customLegends／modifiedLegends 格式，上限 30 MB。匯入在頁面記憶體處理；讀取失敗會保留原本已載入的資料。

若顯示無法連線，先看啟動終端是否仍在執行、是否印出成功地址。若顯示連接埠被占用，可選另一個未用連接埠，例如 `--port 8878`，並使用終端輸出的新網址。不要直接結束來源不明的占用進程。

## 第一次試用

1. 在案卷館選一案；六案都可直接開始。先讀情境，再依三章讀材料與核對題。
2. 展開來源，查看原紀年、記述、篇章與限制。將重要材料加入調查桌並分類。
3. 在人物原典搜尋已載入人物，可選二至三筆對讀；選取原分析段落加入案卷或自由調查。
4. 完成「我的評議」：留下自己的解釋、另一種解釋或反證，以及未解問題。符合材料與任務條件後收藏評議。
5. 用「匯出書桌備份」下載 JSON，確認下次可接續。原人物檔需另行保留。

任務檢查材料的讀法；最後的立場由玩家署名。原長文缺失不妨礙結案。尚未連入楚漢資料包的原庫人物可以閱讀、對讀和作解讀材料，但不因此自動取得來源化事件關係。

## 存檔與私人內容

書桌以 localStorage 自動保存在同一網址來源、同一瀏覽器，包含進度、材料引用、筆記、評議版本、自由調查及創作工坊選擇。原文章全文不會自動存入書桌；原文 ID、欄位、段號與內容指紋用於之後重新讀取同一人物檔。

更換連接埠、用 localhost 代替 127.0.0.1、換瀏覽器或清除網站資料，不能保證看到原位置的 localStorage。先匯出書桌，再在新位置用「匯入書桌備份」接續。這個檔案包含玩家自行寫入或貼入筆記的文字。

匯入先顯示摘要與版本提示，再選合併或接續匯入版本。同案不同內容保留為草稿，自由調查同題差異另存副本；已收藏評議可回看並以某版繼續修訂，還原前保留當前草稿。

如果頁首提示僅留在本頁、存檔需處理或另一分頁已更新，開啟「管理本機存檔」，先下載目前工作或保留的原檔，再依提示恢復保存。未知或損壞的舊檔不會被自動覆寫。原文內容改動時，材料卡會標示段落或全文脈絡的變更，需重新核對。

一般長文欄位最多 20,000 字元，材料筆記最多 10,000 字元。若最新輸入因限制未能加入書桌，使用「檢視並備份未保存草稿」下載全文 `.txt`，也可另下載已保存版本 `.json`。先保留這些文字再縮短或處理上限；上次有效的書桌 JSON 並不包含被拒絕的最新文字。

## 重建與檢查

在 `app` 根目錄執行：

```powershell
node scripts/build-history-schema.cjs
node scripts/build-history-case-schema.cjs
node scripts/build-chuhan-package.cjs
node scripts/validate-history.cjs
node scripts/build-chuhan-package.cjs --check
node --test tests/history-data.test.cjs tests/history-investigation.test.cjs tests/history-build.test.cjs tests/history-case-schema.test.cjs tests/history-preview.test.cjs
```

預設驗證同時包含共用包與案件集。建置讀取五份已保存研究輸入，包含本次 `investigation-supplement.json` 的 20 條主張；案件文字與引用仍需按 [編寫規則](history-case-authoring.md) 人工核對。

如果有同一份私人完整陣列，可另做身份對應核對：

```powershell
node scripts/build-chuhan-package.cjs --check --verify-library "../資料備份_2026-09-30/962人物完整資料.json"
```

這項核對不會寫回原人物檔。程式測試主要檢查資料與引用、存檔版本、匯入復原、預覽端點等行為；不能代替來源核讀、真實瀏覽器排版檢查或玩家試玩。

## 隨既有後端發布

既有後端 `backend/main.py` 已提供 `/history-lab`，並以 `/static` 提供工作台資產。公開發布沿用既有後端流程，需一併包含：

- `backend/history-lab.html` 與其 CSS、JavaScript。
- `history-data.js`、`history-investigation.js`、`history-lab.js`。
- 共用 schema、楚漢資料包與案件集 JSON。
- 內建 `legends.js`，以及本次工作台的本地美術資產和來源記錄。

獨立 Node 預覽僅監聽 127.0.0.1，適合本機檢視，不是公開部署服務。`--library` 指定的私人檔與 `/private-library.json` 僅屬本機預覽；不要把私人快照、人物長文或書桌備份放入公開靜態目錄。

本工作台的互動不呼叫模型或向雲端寫入人物資料。發布前確認資料包與案件集版本相容、來源鏈接可用、缺少私人人物檔時仍能以內建庫操作，並帶著目前的來源與覆蓋限制發布。正式對外狀態以實際部署結果為準。
