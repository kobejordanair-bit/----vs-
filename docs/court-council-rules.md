# 缺糧朝會：多方議政與組合政令

## 這版要驗證的玩法

這是三回合、跨時代的架空朝堂。韓信、蕭何、魏徵的能力、立場與互動由作者依史料線索改編，政策與數值不是史實重演。原人物資料、文章與 v1 存檔不由本引擎修改。每次遊玩只跑固定規則，不呼叫 AI、不使用隨機數、不依賴時間。

玩家每回合制定一份政令：**一項主措施＋零或一項配套＋一位執行者＋授權方式**。三位人物與五個利益方都針對同一份草案回應。推薦草案是可修改的起點。

## 決策欄位

| 欄位 | ID | 用途 |
|---|---|---|
| 主措施 | `route`、`market`、`levy`、`ration`、`audit`、`fortify`、`diplomacy` | 各回合開放五至六項；議和只在第二回合、查帳在第一與第三回合 |
| 配套 | `none`、`relief`、`reserve`、`ledger`、`vouchers`、`settle`、`default` | 最多一項，使用執行人手與真實資源 |
| 執行者 | `hanXin`、`xiaoHe`、`weiZheng` | 改變方法、前後批交付、成本與責任人 |
| 授權 | `bounded`、`flexible` | 限額程序或臨機處置；臨機處置有民心與朝廷合作成本 |

政令只接受上述四個欄位，不接受額外鍵、任意人物或組合清單。到期承諾必須用配套欄明確選擇 `settle` 或 `default`，因此本回合不能再加其他配套；主措施、執行者、授權仍可調整。

## 人物差異如何進入規則

| 人物 | 同一份修復糧道政令的執行差異 | 其他情境與記憶 |
|---|---|---|
| 韓信 | 限額軍令沿既定路線，後批十糧；臨機權可做地形佯動，後批二十四糧，同時多占協調人手、抽調巡防並付出政治成本 | 邊防至少五十時支持按兵議和；查帳時查軍中空額；記住具體授權被收回 |
| 蕭何 | 對圖籍辨識近倉，立即多開四糧，遠倉十六糧另排運期；徵役仍傷民戶 | 按戶籍排除重徵、核對商糧合約、接續軍隊替補；可以為韓信的糧隊作保 |
| 魏徵 | 公開徵役與配給理由，分批驗糧，運量較小、配給更可核對 | 在限額與補償具備時支持徵糧；檢查失約，反對仍盡職；公開查核也使地方官承擔責任 |

`route + ledger + xiaoHe + bounded` 可以得到三位人物支持；`levy + ledger + xiaoHe + flexible` 可以得到韓信與蕭何支持、魏徵反對。反對本身不扣信任。低信任增加責任確認的人手，專業能力不消失。

### 蕭何與韓信的共同責任

韓信護運加上公開糧帳時，蕭何核對戶籍與運期，兩人合作提高七，形成一批可核對的交付。**只有這批擔保糧實際抵達，且合作至少五十七**，下一次韓信臨機護運才可沿用交接程序，免去一份重複協調人手。單純宣布擔保不能立刻取得此條件。這段關係由本局選擇形成，不預設永久同盟。

### 個人記憶

每人保留 `mandate`、`commissions`、`honored`、`breached` 與 `events`。紀錄包括：哪回合受命、採哪種授權、是否突然收權、由誰擔保、到期款項付清或撤回、實際糧車回報。再次任命同一人物，把臨機權改成限額且沒有公開交接程序，該人物信任減四；有公開糧帳則不扣。任命增加一點合作信任，不能抵消大額失約後果。

## 五個利益方會改變後續執行

| 利益方 | 合作條件 | 真實影響 |
|---|---|---|
| 邊軍 | 低於四十 | 遠倉護衛不足，該次政令的後批少四糧 |
| 農戶 | 低於四十五 | 藏糧使該次徵糧少五糧 |
| 商戶 | 低於四十五／至少六十五 | 採買基本款加四／減二國庫 |
| 地方官與倉吏 | 低於三十五 | 修路多占一份協調人手 |
| 朝廷議政者 | 低於三十五 | 總協調人手由四降為三 |

合作條件在下令時決定，已派出的糧車不會被後來的選擇追溯改寫。草案顯示當前合作、立即變化、在途回報的資源與利益方變化。人物關係與合作紀錄依照完整政令回放驗證。

## 組合需要協調與預算

主措施人手：重排配給一，糧道、商糧、徵糧、查帳、議和二，增援三。配套人手：救急二，軍糧、公開帳、憑券、履約一，無配套或撤回零。韓信臨機護運通常再加一；低信任也再加一。

- 沒有先建立公開戶籍帳，不能同批徵糧又賑濟，因為無法區分徵收與救助對象；前一回合建立帳後才可混合。
- 限額補償憑券只配徵糧，而且與臨機超出程序的授權互斥。
- 增援加救急一般需要五份人手，超出當前協調能力。
- 四糧保留給護衛就會真正花掉，不能同時計成賑濟。
- 合併檢查全部成本，頒令前必須付得起；本令新增糧與尚未抵達的收益不能倒填付款能力。
- `ration` 沒有成本，也沒有新增糧。它只改變現有配給順位，確保資源極低時仍能作出一份有後果的命令。

## 承諾不能免費延到局外

| 承諾 | 立即成本 | 到期付款 | 按期履約 | 公開撤回 |
|---|---|---|---|---|
| 徵糧補償憑券 | 二國庫辦理 | 下一回合九國庫 | 民心 +5 | 民心 −12 |
| 接續糧餉 | 增援本身的糧餉 | 下一回合四糧、四國庫 | 邊防 +3 | 邊防 −10、民心 −3 |

按期履約：責任人信任 +5、魏徵信任 +2、受益方合作 +7。撤回：責任人信任 −8、魏徵信任 −6、受益方合作 −15。責任人若是魏徵，兩項信任合併結算。草案會顯示兩條路的具體數字。

第三回合的新補償與續餉必須當場付款，付款成本與履約效果直接併入本令。第三回合結束時，`pending` 與 `commitments` 都為空，責任紀錄仍保留。

## 危局持續與完整結算預覽

每回合依序：

1. 執行政令，付款與到期承諾一起結算。
2. 接收本回合應到的先前糧車與新派回報。
3. 維持基本軍民供給：耗九糧、兩國庫。
4. 第二回合的敵方試探減三邊防，第三回合減四。

供給不足九糧時耗盡可用糧，另減六民心、四邊防。國庫不足二時只支付可用款，未付日常工資另減二民心。全部變化受零至一百界限約束並留下通知。糧車先到貨再供給，不會故意把已到糧算成欠糧。

`evaluateOrder` 顯示：

- `effects`：主措施、配套與到期承諾的立即淨變化。
- `pendingPreview`：先前在途與本令新派的日期、資源與利益方合作變化。
- `commitmentPreview`：本次到期、新承諾、付款額與履約／撤回代價。
- `worldPreview`：固定消耗、邊境試探與本令預計觸發的缺供後果。
- `resolutionEffects`：整個回合的資源淨變化，與 `choose` 的最後一筆 `changes` 完全相同；不可下令的草案為 `null`。

完整預估直接使用同一個純函式結算器，沒有另一套估算數值。連續三次零成本重排配給後，起始四十二糧只剩十五糧，會得到危局結局；等待不是穩贏方案。

## 狀態與存檔契約

引擎 UMD 為 `DynastyCouncil`，CommonJS 可直接 `require`。公開 API：`createGame`、`getScene`、`getCatalog`、`evaluateOrder`、`choose`、`getEnding`、`validateState`、`exportReplay`、`importReplay`，以及凍結的 `ADVISORS`、`STAKEHOLDERS`。

狀態識別：`version: 2`、`scenario: 'court-grain-v2'`，與 v1 完全分開。每筆 `log.order` 是精確四欄位的完整政令；驗證由初始狀態重跑全部命令，逐鍵比對所有資源、合作、關係、授權、記憶、回報、承諾與台詞。多出欄位、修改結局、改資源或偽造記憶都會被拒絕。這是回放一致性檢查，沒有聲稱伺服器簽章或防作弊。

本引擎不操作 `localStorage`、雲端、人物文章或帳戶；保存、匯入和 UI 隔離由外層處理。回放 JSON 字串上限為 120,000 字元，UI 匯入檔案上限為 512 KB，不包含原人物分析、帳號或憑證。

## 驗收

`node --test tests/court-council.test.cjs`：二十項測試覆蓋多方支持／反對、不同執行方法、授權、組合限制、真正履約與失約、末回合預付款、已交付擔保的後續用途、利益方成本、預估與實際一致、持續危局、短糧代價、不可變回放及篡改拒絕。

分支檢查遍歷所有初始合法組合，再選取每個「主措施＋執行者」的不同首回合狀態，遍歷其合法第二回合組合，確認第三回合仍有可負擔退路。退路的規則性保證是：重排配給無成本；有到期款可公開撤回；人手最多二，低於最低協調上限三。這保證能下令，不保證能得到好結局。
